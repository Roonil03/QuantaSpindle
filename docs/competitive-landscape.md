# QuantaSpindle competitive landscape and naming checks

Research date: 2026-11-15. Sources are original project documentation, authors' papers, official package indexes and official government/international organization pages. This is a bounded engineering survey, not a market census, benchmark ranking, originality certificate or legal clearance. No third-party source code was copied. The conclusions below are design judgments, separated from observed capabilities.

## Reference and adjacent projects

**stock-simulations.** The requested [GitHub repository](https://github.com/e-wrobel/stock-simulations) returned HTTP 404. Its [pkg.go.dev module index](https://pkg.go.dev/github.com/e-wrobel/stock-simulations) was accessible and displayed an October 2023 pseudo-version with GPL-3.0 metadata. The indexed README describes configurable stock Brownian simulations, MySQL persistence and CPU-core configuration. These are indexed claims, not source-verified behavior. A 404 cannot establish whether the project is deleted, private or temporarily unavailable. QuantaSpindle should offer an independent importable API, explicit reproducibility/validation contracts and optional accelerator integration; the limited reference access does not support claims that these features are absent from every version of the reference.

**QuantLib.** Its [official project page](https://www.quantlib.org/) describes a broad C++ framework for quantitative finance, modeling, trading and risk with bindings to several languages and a modified BSD license. Its breadth makes it a stronger candidate when a user needs a mature pricing ecosystem. QuantaSpindle's intended contribution is a focused Go scenario API and transparent execution backends, not a claim to replace QuantLib or provide comparable instrument coverage.

**Gonum.** The [officially indexed matrix package](https://pkg.go.dev/gonum.org/v1/gonum/mat) provides matrix types and decompositions, including Cholesky, under BSD-3-Clause metadata. It is numerical infrastructure rather than an end-to-end scenario/risk workflow. A minimal dependency-free Cholesky can serve the first foundation; larger linear algebra needs should prompt a dependency versus maintenance review instead of growing a competing general matrix library.

**NVIDIA cuRAND.** The [CUDA 13.2 device API guide](https://docs.nvidia.com/cuda/archive/13.2.0/curand/device-api-overview.html) documents GPU pseudorandom generation including Philox. It supplies a building block, not Go model validation, portfolio semantics or publication. QuantaSpindle can add a small Go-facing runner contract while keeping NVIDIA's runtime/toolkit requirements explicit. There is no presumption that every workload benefits from GPU execution.

**Markov tooling.** The [markovchain authors' documentation](https://cran.r-project.org/web/packages/markovchain/vignettes/an_introduction_to_markovchain_package.pdf) covers finite-state chains in R. [MSwM's CRAN page](https://cran.r-project.org/package=MSwM) describes estimation and diagnostics for univariate autoregressive Markov-switching models. QuantaSpindle's foundation simulates caller-specified regimes and does not match those estimation capabilities. Keeping this distinction visible avoids presenting a scenario state machine as a calibrated econometric regime model.

**Execution research.** [Almgren and Chriss](https://static1.squarespace.com/static/5df018ec4c9d61288094246c/t/5e39db229a16b072d97fce9b/1580849954431/Optimal%2BExecution%2Bof%2BPortfolio%2BTransaction%2B_%2BAlmgren%26Chriss%2B1999.pdf) analyze execution costs and risk with permanent/temporary market impact. A lightweight execution-cost overlay is useful for sensitivity scenarios, but it does not establish optimal execution or reproduce empirical microstructure. All coefficients remain explicit caller inputs.

## Product position and limits

The proposed niche is a small Go-first scenario engine: seeded streams tied to scenario identity, bounded workers, correlated GBM and explicit regime timing, terminal portfolio risk, a separately selectable real CUDA runner, and reproducible benchmark commands. This combination is a design choice, not evidence that no comparable project exists. CPU results should be useful without a database, GPU, native compiler or container. No feature is advertised as complete merely because it appears in this review.

The strongest reasons to choose another tool are broad derivatives/pricing coverage (QuantLib), advanced matrix/statistical infrastructure (Gonum), or regime fitting and inference (specialist econometric tools). Financial model validation and real market calibration remain distinct from software correctness. Avoid performance superiority claims until controlled end-to-end measurements exist.
